Operational Challenges

The Problem: Friction in Traditional Hostel Living

01

Manual Registers

Complaints written in physical registers are frequently misplaced, unreadable, or ignored with zero audit trail.

02

No Student Tracking

Students have no status visibility. They cannot know whether an electrician or plumber was dispatched.

03

Untriaged Emergencies

Urgent hazards (sparking switches, burst pipes) sit in the same queue as routine carpentry with no priority flags.

04

Fragmented Notices

Curfew circulars and water cuts get buried in informal chat channels or posted on physical boards seen too late.

Core Need: A single digital platform that automates ticket triage, enforces strict administrative accountability, and broadcasts actionable notices to specific hostel blocks.
Speaker Notes: "In collegiate environments like IIT Bhilai, residential students frequently encounter facility issues. The conventional approach involves handwritten registers in caretaker offices. This results in four key issues: zero real-time tracking for students, lack of automated prioritization for urgent hazards, fragmented broadcast notices, and absence of accountability. Our goal was to engineer a purpose-built system that automates triage, secures access, and keeps every resident informed."

Full-Stack Blueprint

System Architecture & Technology Stack

Frontend (Client Layer)

Vanilla HTML5 • CSS3 • ES6+ JavaScript

Sub-50ms render times, zero framework bundle bloat, responsive custom properties, accessible ARIA toasts.

Backend (API Layer)

FastAPI (Python 3.14) • Uvicorn ASGI

Asynchronous endpoints, strict Pydantic schema validation, centralized CORS, modular routers (/auth, /issues, /announcements).

Data & Security Layer

SQLite3 • JWT (HS256) • pwdlib (Argon2)

Relational foreign keys with cascade delete, 60-min token expiration, secure password hashing.

Access Governance

Security Architecture & Role-Based Access Control

Capability / Operation Student Role Warden Role Admin Role
Dashboard & Profile Access Allowed Allowed Allowed
Raise Maintenance Issue Allowed Allowed Allowed
Delete Issue Self-Owned Only Any Issue Any Issue
Update Issue Status (Resolved/Pending) Blocked (403) Allowed Allowed
View Announcements Feed Allowed Allowed Allowed
Broadcast Announcement Blocked (403) Allowed Allowed
Dual-Layer Enforcement: Client scripts dynamically adapt the DOM (hiding unauthorized buttons), while backend FastAPI route dependencies verify JWT claims. Any unauthorized direct API call returns 403 Forbidden.
Speaker Notes: "Security was designed from day one with defense-in-depth principles. Authentication uses signed JWT Bearer tokens with automated expiration. More importantly, we enforce a strict Role-Based Access Control matrix. A student can only delete issues that belong to their specific account, verified on the backend by matching user IDs and emails. Administrative actions—such as marking issues resolved or posting hostel announcements—are restricted strictly to wardens and admins."

Resilient Fallback Design

What happens when third-party APIs face rate limits, network timeouts, or offline environments?

Category → "Not Defined"
Priority → "Medium"
Summary → Clean First 100 Characters

• Zero server crashes • Zero rejected student tickets • Instant fail-safe response

Speaker Notes: "One of our portal's standout capabilities is AI-assisted triage. Traditionally, students misclassify technical issues or caretakers have to read lengthy paragraphs to gauge urgency. We integrated Google Gemini to parse plain text into structured fields: Category, Priority, and Summary. Crucially, we designed this for resilience. If the API is offline or faces network timeouts, our backend doesn't crash; it gracefully defaults to 'Not Defined' category and 'Medium' priority."

Persistence Layer

Database Schema & Relational Architecture

users

  • id: INTEGER PRIMARY KEY
  • email: TEXT UNIQUE NOT NULL
  • password_hash: TEXT NOT NULL
  • role: CHECK(role IN ('student', 'warden', 'admin'))

issues

  • id: INTEGER PRIMARY KEY
  • user_id: FK → users(id) ON DELETE CASCADE
  • email, student_id, student_name
  • room_number, hostel, phone
  • title, description, summary
  • category, priority, status
  • raised_on, resolved_on, remarks

announcements

  • id: INTEGER PRIMARY KEY
  • category, date, title
  • summary, team, body
  • details: TEXT (JSON Object)
  • created_at: TIMESTAMP
Integrity Highlights: Foreign keys enforced via SQLite pragmas. Cascading deletes guarantee orphaned records are cleaned if an account is removed. JSON-serialized columns provide extensible metadata storage.
Speaker Notes: "Behind our API lies a clean, relational SQLite database. The schema consists of three core entities: users, issues, and announcements. Foreign keys are enforced with cascading deletes. Notice the flexibility of the issues and announcements tables: we store structured attributes like dates, status, and room numbers alongside JSON-serialized details for rich metadata. Check constraints ensure that roles and statuses remain within authorized enums."
Code Quality • Best Practices

Engineering Rigor & Production Considerations

Zero Framework Bloat

Total JS client footprint under 50KB. No heavy React/Angular/Vue dependencies, resulting in lightning-fast initial load times.

Box Model Defense

Strict box-sizing: border-box and overflow-wrap: break-word prevent text overflow across long issue cards.

Micro-Interactions

Subtle opacity hover feedback (opacity: 0.85) replacing harsh color flashes for consistent brand styling.

Resilient Fallbacks

Graceful degradation when AI services are unreachable, ensuring zero operational downtime for student filings.

Speaker Notes: "Throughout the project lifecycle, we emphasized engineering rigor over quick shortcuts. We tackled subtle front-end edge cases—such as long text strings breaking card boundaries—by enforcing rigorous overflow wrapping. We ensured our UI micro-interactions feel cohesive by standardizing on opacity transitions. And critically, our frontend delivers sub-50-millisecond initial loads because it is completely free of bulky JavaScript libraries or external CSS frameworks."
